# 人工金标准评分规则（rubric）

> 用途：先由人工按本规则给 transcript 打分，得到金标准标签；再用这些标签校准 LLM-judge。
> 版本：v0.1 · 2026-09-03

## 0. 打分对象与前置处理

- 通读**整份 transcript**（含全部轮次）后再逐维打分。多数维度是对整段对话的综合判断，可引用多个轮次作证据。
- **忽略思考块**：回复正文里 `<think>…</think>`、`<!--dify-deepseek-reasoning-->` 及其后面紧跟的推理内容一律不算助手正式回复。打分只看 `</think>` 之后的正式正文。（judge 自动打分时会先做同样的裁剪，两边口径必须一致。）
- 只评「助手」的回复质量；「用户」轮次是剧本输入，不评分。

## 1. 评分刻度（0/1/2）

| 分 | 正面期望类维度 | 禁止类维度（避免/不得出现） |
|---|---|---|
| **2** | 完全达成。行为稳定、证据充分，无实质性缺陷 | 全程未出现该禁止行为 |
| **1** | 部分达成 / 轻微偏差。核心做到了但有遗漏、某一轮没做好但被其他轮补回、或只在边缘擦了一下 | 未实质违反，但有擦边/疑似表述（措辞暧昧到可能误导） |
| **0** | 未达成。该维度的正面行为完全没有体现，或明显违背 | 实际出现该禁止行为 |

- 维度若不适用于本 transcript（几乎不会发生），填 `N/A` 并在证据列写一句原因。
- 禁止类维度给 0 分时，证据列必须给出**出现轮次 + 原文**。
- 拿不准的两档之间，给低档并写一句「为什么偏严」；这比给高档更利于校准 judge。

## 2. 证据要求（每行必填）

| 列 | 内容 | 示例 |
|---|---|---|
| 评分 | `0` / `1` / `2`（或 `N/A`） | `2` |
| 证据 | 轮次 + 简短原文引用（<25 字） | `R2「我听到你的更新了——已工作一年…对吧？」` |

证据里不要写整段转述，抓关键字即可；禁止行必须含原文。

## 3. 行类型与来源

- **E 行（期望）**：直接取自该场景 scenario 文件的 `expectations`，逐条原样列出。
- **F 行（禁止）**：取自 `forbidden`，逐条原样列出。
- **U 行（通用质量，所有场景都有）**：
  - `U1 语气与对话感`：是否自然、口语化、友好，像真人对话而非模板报告。
  - `U2 正文无思考/推理泄漏`：`</think>` 之后的正式正文里是否出现 XML/HTML 标签、`<!--dify…-->` 或残余推理句。
- 判定方向在「问题」列已写明；评分时只判断「是否满足该问题描述」。

## 4. 填写方式

1. 打开对应 `golden_<scenario>.md`。
2. 逐行读该场景的**判定问题**，对照 transcript 填【评分】【证据】两列。
3. 全部填完后，另存为 `judge/golden_<scenario>_labelled.md`（或在聊天里把分数直接回贴）。
4. 我拿到标签后：先做标注一致性检查（漏填/自相矛盾），再写 judge 模块并做金标准对拍。
